# 07. Методология и инструментарий

Здесь описано, **чем и как** проводилось исследование. Код и скрипты не
публикуются (см. [NOTICE](../NOTICE.md)) — но подход полностью воспроизводим
по этому описанию стандартными инструментами.

## Инструменты

| Инструмент | Этап | Роль |
|---|---|---|
| pefile (Python) | Форензика, Phase 1, Phase 2 | Разбор PE-структуры, заголовков, импортов/экспортов |
| objdump | Форензика, Phase 2 | Верификация формата PE64 |
| Capstone (x86-64) | Форензика, эмуляция | Дизассемблирование точки входа и разбор точек остановки |
| xref-анализ | Форензика | Перекрёстные ссылки, классификация строк и структур |
| Unicorn 2.1.4 | Эмуляция | Исполнение образа с минимальным окружением (PEB/TEB, bump-heap, трамплины импортов) |
| GNU as | Phase 2 | Ассемблерный шим выделения памяти |
| Кастомный генератор PE64 | Phase 2 | Побайтовая сборка DLL-заглушек без компилятора C/C++ |
| Собственный симулятор загрузчика | Симуляция | Модель разрешения импортов Windows 10/11 x64 |
| OSINT-сверка | Форензика | Публикации, файл-листы, diff-отчёты сообщества, отчёты песочниц |

## Принципы

1. **Только статический анализ** для исходного образца — без запуска в
   исполняемой среде. Единственное исключение — управляемая эмуляция
   (Unicorn) с нулевым доступом к реальным игровым данным и без сети.
2. **Код образа не модифицируется.** Все изменения — вне секций кода и
   данных: только два поля PE-заголовка.
3. **Внешние заглушки вместо правок.** Любая «недостающая» подсистема
   закрывается внешней DLL рядом с exe, а не правкой образа — это обратимо
   и не порождает изменённой копии игры.
4. **Управляемый отказ.** Заглушки возвращают осмысленные значения
   (S_OK/NULL), чтобы отличать «нет подсистемы» от «крах кода».
5. **Воспроизводимость.** Каждый вывод подтверждён отдельным проверяемым
   артефактом (отчёт симуляции, трассировка эмуляции, верификация заглушек).

## Последовательность работ

1. **Форензика подлинности** → вывод: образец согласуется с подлинной
   консольной сборкой GTA VI (см. [01](01-object-and-authenticity.md)).
2. **Phase 1** → образ принимается загрузчиком Windows
   ([02](02-phase1-pe-header.md)).
3. **Phase 2** → 587/587 импортов связываются, `STATUS_DLL_NOT_FOUND`
   устранён ([03](03-phase2-import-stubs.md), [04](04-loader-simulation.md)).
4. **Эмуляция** → TLS-колбэки исполняются, остановка на обязательных
   статических инициализаторах ([05](05-boot-emulation.md)).
5. **Разбор предела** → полный запуск требует эмулятора уровня консоли и
   игровых пакетов ([06](06-why-full-boot-impossible.md)).

## Ограничения метода

- Отсутствие Authenticode-подписи у GXDK-сборок делает вывод о подлинности
  вероятностным («согласуется с подлинностью»), а не абсолютным.
- Симуляция загрузчика — модель, а не реальный запуск; но именно она
  позволила изолировать барьеры по уровням.
- Эмуляция ограничена пользовательским окружением без игровой ОС — это
  осознанная граница исследования, а не недоработка.
