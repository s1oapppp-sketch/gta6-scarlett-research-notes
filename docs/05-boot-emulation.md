# 05. Эмуляционная загрузка на Unicorn

## Цель

После успешной симуляции загрузчика следующий вопрос: а что происходит с кодом
*дальше* — на уровне исполнения инструкций? Проверено эмуляцией: образ
исполнялся в эмуляторе **Unicorn 2.1.4** (x64) с минимальной эмуляцией
пользовательского окружения.

## Настройка окружения

- минимальные структуры PEB/TEB;
- bump-heap (простейший аллокатор памяти);
- все 587 импортов перехвачены трамплинами на заглушки;
- отображение секций образа по PE-заголовкам.

## Что произошло

| Событие | Значение |
|---|---|
| TLS-колбэков выполнено | 2 |
| Вызовов импортов до остановки | 0 (до импортов дело не дошло) |
| Инструкций выполнено | 275 |
| Стоп-причина | **INVALID READ @0x0** — чтение по нулевому указателю |

## Разбор точки остановки

Выполнение дошло до CRT-стартапа и остановилось там, где разыменовывается
глобальный указатель, который заполняют **статические инициализаторы**.
Причина проста: в симуляции загрузчика `_initterm` / `_initterm_e` были
заглушками, вернувшими 0 — статические инициализаторы **не исполнялись**.
Их список в образе пуст не потому, что его нет, а потому что заполнение
требует фактического исполнения инициализирующего кода, а не связывания.

Вывод, подтверждённый этим экспериментом:

> **Статические инициализаторы CRT — обязательная фаза запуска движка.**
> Без их выполнения (а для их выполнения нужно реальное окружение CRT,
> а не заглушки) образ не переходит к инициализации RAGE.

Инструкции вокруг точки остановки при этом показывают корректное,
осмысленное поведение кода (разбор таблицы секций PE в памяти) — код жив,
управляем и исполняется ровно так, как задумано; он просто ожидает
окружение, которого эмулятор на этом уровне не даёт.

## Что это значит

- Прохождение загрузчика Windows (Phase 1+2) — необходимое, но недостаточное
  условие;
- следующий барьер — не «крах файла», а отсутствие окружения инициализации;
- полноценный старт требует уровня эмуляции, описанного в
  [06-why-full-boot-impossible.md](06-why-full-boot-impossible.md).
