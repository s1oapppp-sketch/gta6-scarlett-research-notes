# 04. Симуляция загрузчика Windows

## Цель

Доказать, что после Phase 1 + Phase 2 загрузчик Windows 10/11 x64 доводит
образ до точки входа, не споткнувшись ни об один импорт.

## Модель

- DLL ищутся сначала в каталоге приложения, затем системные (стандартный
  порядок Windows);
- заглушки комплекта лежат рядом с exe;
- для каждого системного модуля проверена доступность на стандартной
  Windows 10/11 x64 (api-set, VC++ 2015–2022 Redistributable, системные DLL).

## Результат: 68/68 модулей, 587/587 функций

| Показатель | Значение |
|---|---|
| DLL в import-таблице | **68** |
| — системные Windows / api-set / VC++ | 56 |
| — заглушки комплекта | 12 |
| Функций всего | **587** |
| Разрешено (bound) | **587** |
| Не разрешено | 0 |
| Ошибки | нет |

Крупнейшие системные зависимости: MSVCP140.dll (113 функций), api-ms-win-crt-math
(41), libHttpClient.GDK (38), api-ms-win-crt-string (31), api-ms-win-crt-stdio
(29), WS2_32 (25), VCRUNTIME140 (23), api-ms-win-core-file (22), api-ms-win-core-synch
(17+), WINHTTP (15) — то есть **более 80% импортов — это обычные Windows/CRT-функции**.

Проверки образа перед связыванием — все пройдены: `MZ`, x64, PE32+, подсистема
GUI, отсутствие FORCE_INTEGRITY (снят в Phase 1), отсутствие сертификата,
NX_COMPAT, корректная контрольная сумма.

## Следствие

`STATUS_DLL_NOT_FOUND (0xC0000135)` на шаге разрешения импортов **больше не
возникает**. Порядок прохождения:

1. валидация заголовков;
2. отображение 10 секций;
3. TLS-колбэки (CRT);
4. разрешение всех 68 модулей;
5. связывание всех 587 функций;
6. точка входа `mainCRTStartup`;
7. CRT/RAGE-инициализация — и здесь начинаются реальные ограничения, см.
   [05-boot-emulation.md](05-boot-emulation.md).

## Предел модификации

Без реализации аппаратных сервисов Xbox (D3D12X Scarlett, XG, CHAD/APU/ACP,
BVH-ускоритель) игровой цикл не запустится. Это уже уровень **эмулятора
консоли**, а не правки файла — подробный разбор в
[06-why-full-boot-impossible.md](06-why-full-boot-impossible.md).
