# 06. Почему полный запуск невозможен без эмулятора

Это главный итог всего исследования. Ниже — инженерное обоснование, почему
дальше «правки файлов» путь закрыт.

## Три уровня барьеров

### 1. Формат файла — пройден (Phase 1)

Тривиальные правки заголовков делают образ принимаемым загрузчиком Windows.
Пройдено.

### 2. Связывание импортов — пройдено (Phase 2 + симуляция)

587/587 функций связываются: 56 системных модулей Windows + 12 заглушек.
`STATUS_DLL_NOT_FOUND` устранён. Пройдено.

### 3. Инициализация движка — не пройден (эмуляция остановилась здесь)

Дальше требуются подсистемы, которые заглушками не воспроизводятся в
принципе:

## Чего не хватает (и что нельзя «заглушить»)

| Подсистема | Что ожидает движок | Почему заглушка не помогает |
|---|---|---|
| **D3D12X Scarlett** | `D3D12XboxCreateDevice` — устройство Scarlett с enhanced barriers, work graphs, метакомандами | ПК-устройство D3D12 этим API стать не может: консольные расширения графического конвейера отсутствуют на Windows |
| **Аудио-стек CHAD / APU / ACP** | Аппаратный аудио-копроцессор консоли и его HAL | Требует эмуляции аппаратуры, а не возврата S_OK |
| **XboxBvhBuilder** | Аппаратный BVH-ускоритель (ray tracing структуры) | Аппаратный блок консоли |
| **XG (xg_xs)** | Низкоуровневое управление графическим конвейером | Консольные команды планирования GPU |
| **Пакеты данных RAGE** | `common:/`, `levels/`, `americas://` — игровое содержимое | Их в утечке не было и они не распространяются |

## Итоговая формула

```
полный запуск =
  адаптация PE-заголовков            (сделано, тривиально)
+ связывание импортов                (сделано, 587/587)
+ эмуляция ОС Xbox Scarlett          (не сделано, проект уровня Xenia, годы работы)
+ эмуляция аппаратных сервисов       (D3D12X, CHAD/APU/ACP, BVH, XG)
+ игровые пакеты данных              (отсутствуют в утечке)
```

Два последних слагаемых на порядок превышают масштаб «портирования файла».
Это уже разработка **эмулятора консоли** — многолетний командный проект
уровня Xenia (эмулятор Xbox 360, развивающийся больше десятилетия).

## Честный прогноз поведения образца на ПК

При текущем уровне адаптации типичный исход — ошибочный диалог или тихий
выход движка на этапе инициализации рендера. Это **не крах на первом вызове
заглушки**: возвратные значения контролируются, движок уходит в управляемый
отказ, встретив отсутствие консольной графической подсистемы.

## Вывод

Файл не «сломан» и не «защищён от ПК» — он **никогда не предназначался
для ПК**. Консольные сборки Series X|S близки к Windows x64 ровно настолько,
чтобы пройти загрузчик и инициализацию CRT, но их движок ожидает платформу,
которой на ПК нет. Документируя это, исследование закрывает вопрос: между
«exe лежит на диске» и «игра запустилась» стоит пропасть масштаба
разработки эмулятора.
